# 2026-10-22 — Training the FNO on a Colab A100

These steps train the FNO on a Google Colab A100 and bring the records back to the Mac. They run
`scripts/probes/probe_fno_libraries.py`, which trains this study's `FNO2d` (`--library apno`), the
NeuralOperator FNO or the PhysicsNeMo FNO through the S2 pipeline. What the probe does is in
`docs/notes/2026-10-21-fno-libraries.md`.

Nothing here has run on Colab yet. The steps were rehearsed on a CPU-only Linux machine, from a
fresh clone of the branch, with a stand-in dataset on a stand-in Drive folder: the clone, the links,
the installs, every training command (with `--device cpu`), the summary cell and the checkpoint
reloads all ran. Not checked: the Colab-only lines (`drive.mount`, `%cd`, `%env`, the `!` loops),
anything that needs a GPU, and the timings.

## Before you start

- **Use the probe, not `scripts/s2_operator.py`.** The S2 script rewrites `results/s2/runs.json`
  and `tuning.json`, which are committed and record the MPS runs; a Colab clone that ran it would
  carry overwritten records. The probe writes only to `runs/fno_lib/` and `runs/predictions_lib/`,
  which are git-ignored and are never read by S4. Its `apno` runs use the same model, features,
  targets, prefix sets, loss A and training loop as S2.
- **The branch.** The probe and the CUDA default of `train_fno.default_device()` are on
  `claude/wizardly-fermi-0y5ast`. Clone that branch until it is merged into `main`.
- **A paid runtime.** The A100 runtime needs a paid Colab plan or compute units.

## 1. On the Mac: put the dataset on Google Drive

Only `data/hdf5/256x97.h5` is needed: 1,084 cases in float32, about 650 MB. Record its checksum,
then upload it to `My Drive/airfoil-pinn-no/data/hdf5/` with the Drive web page or Drive for
desktop.

```bash
shasum -a 256 data/hdf5/256x97.h5
```

The file holds the test splits too. The loader refuses to train on them (`load_split`), and the
probe reads them only through `load_features_only`, as S2 does.

## 5. Match the Mac's precision

On an A100, cuDNN runs float32 convolutions in TF32, a reduced-precision format, unless told
otherwise, and every FNO here uses 1×1 convolutions. The S2 runs on the Mac were full float32. This
setting turns TF32 off for every process started from the notebook:

```python
%env NVIDIA_TF32_OVERRIDE=0
```

Leave it set for every run below, or the GPU runs are not like for like with S2.

## 6. A timing run

Three epochs of this study's FNO on the full training set. Its record goes to a separate folder so
it is not mistaken for the real run; its prediction file is overwritten by step 7.

```python
!python scripts/probes/probe_fno_libraries.py --library apno --n-train 896 --epochs 3 --device cuda --runs runs/fno_lib_timing
```

Each epoch's cumulative wall time is in `runs/fno_lib_timing/apno-n896-s0/train.json` (`log`).

## 8. Read the records

```python
import json, pathlib
s2 = {r["tag"]: r for r in json.load(open("results/s2/runs.json"))}
print(f"{'run':24} {'device':6} {'best val':>9} {'epoch':>5} {'L2 256x97':>9} {'transfer':>8} {'wall s':>7} {'s/epoch':>7}")
for p in sorted(pathlib.Path("runs/fno_lib").glob("*/train.json")):
    r = json.loads(p.read_text())
    print(f"{p.parent.name:24} {r['device']:6} {r['best_val']:9.5f} {r['best_epoch']:5d} "
          f"{r['val_rel_l2_256x97']:9.5f} {r['transfer_val_rel_l2']:8.4f} {r['wall_s']:7.0f} "
          f"{r['wall_s'] / r['epochs_run']:7.2f}")
r = s2["fno-n896-s0"]
print(f"{'S2 fno-n896-s0 (Mac)':24} {r['device']:6} {r['best_val']:9.5f} {r['best_epoch']:5d} "
      f"{'':>9} {r['transfer_val_rel_l2']:8.4f} {r['wall_s']:7.0f} {r['wall_s'] / r['epochs_run']:7.2f}")
```

## 9. Back on the Mac

Copy the two folders from `My Drive/airfoil-pinn-no/runs/` into the repository's `runs/`:
`fno_lib/` (records and checkpoints) and `predictions_lib/` (test predictions in the S4 format).
Both are git-ignored, so nothing is committed by accident and nothing collides with S2's files.
Every tensor was moved to the CPU before saving, so the checkpoints load on the Mac as they are.
An `apno` checkpoint loads with `train_fno.load_model`. A library checkpoint loads into
`build_model(library, FnoConfig(**ck["cfg"]))` from the probe, with `load_state_dict(ck["model"])`.

Two things are not in place yet:

- **Scoring the test predictions.** `scripts/s4_score.py` reads only `runs/predictions/` and writes
  the committed `results/s4/`, so it must not be pointed at these files. A scorer for
  `runs/predictions_lib/` is still to be written. Until then, the comparison is on the validation
  numbers in each `train.json`.
- **The findings entry.** When the runs are in, they go into `docs/findings.md` as a dated entry,
  with the commands above, the device, and the GPU wall time recorded as its own cost basis: it is
  not comparable with the Mac times in S2 and S4.
